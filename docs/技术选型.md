## 烟火小食单：技术选型与目录结构设计（V1）

### 1. 技术选型（后端）
- 运行环境：`Java 17`
- Web 框架：`Spring Boot 3 (Spring MVC)`
- 构建方式：`Maven`
- 打包部署：`WAR`（外部 `Tomcat 10+` 部署）
- ORM：`MyBatis`
- 定时任务：`XXL-JOB`
- 接口文档（Swagger）：`springdoc-openapi (Swagger UI)`
  - Swagger UI：`/swagger-ui/index.html`
  - OpenAPI JSON：`/v3/api-docs`
- 数据库：`MySQL 8`
- 缓存（可选但建议保留）：`Redis`
- 鉴权（建议）：`Spring Security + JWT`
- 日志：`Log4j2`
  - 通过 `spring-boot-starter-log4j2` 使用 Log4j2（避免与默认 Logback 冲突）

### 2. 技术选型（前端）
- 管理后台：`Vue 3 + Vite + TypeScript + Element Plus + Pinia + Axios`
- 小程序端：`uni-app (Vue3)`（若后续还要多端复用；仅微信生态可改原生小程序）

### 3. 工程分层约定（后端代码）
- `controller`：只做参数接收、校验与返回统一响应；不写复杂业务逻辑
- `service`：业务逻辑
- `repository/mapper`：数据库访问（MyBatis Mapper + XML 或注解）
- `entity`：持久化实体
- `dto`：请求/响应入参对象（优先 DTO + `@Valid`）
- `config`：Spring/MyBatis/Security/线程池等配置
- `advice`：`@ControllerAdvice` 全局异常处理（统一返回 `{code,message,data}`）

### 4. 统一接口响应约定
- 成功：`code = 0`，`message = "success"`，业务数据在 `data`
- 失败：`code != 0`，`message` 为可读错误信息，`data = null`

## 5. 项目目录结构设计（列举两种）

以下两种属于“工程组织方式”的备选项；两者都遵守同一套分层约定（`controller/service/repository/entity/dto/config/advice`）。


### 方案 B：多模块 Maven（领域/职责分域）
适用：预计快速扩张、希望降低耦合、团队并行开发、领域边界相对清晰。

```text
menu/
  pom.xml                      # parent/聚合工程
  modules/
    admin-api/                 # 对外接口（controller/DTO/校验等）
      pom.xml
      src/main/java/...
      src/main/resources/...

    domain-service/           # 业务逻辑（service/领域/用例）
      pom.xml
      src/main/java/...

    domain-repository/       # 数据访问（mapper/entity/SQL）
      pom.xml
      src/main/java/...
      src/main/resources/...

    common/                    # 通用能力（返回体、异常、工具、通用 DTO）
      pom.xml
      src/main/java/...

    job/                       # XXL-JOB 执行器（定时任务实现）
      pom.xml
      src/main/java/...

  docs/
    技术选型.md
```

要点：
- parent 统一版本与公共依赖治理（dependency management）
- 各模块职责更独立，后期扩展、替换成本更低
- 需要避免循环依赖，模块间依赖方向要清晰
