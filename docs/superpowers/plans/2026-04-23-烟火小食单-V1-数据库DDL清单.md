# 烟火小食单 V1 数据库 DDL 清单（按批次）

## 1. 目的与范围

- 目的：将 `V1` 研发拆分矩阵映射为可执行的数据库建模与 DDL 变更清单。
- 范围：覆盖 `AUTH/DISH/INGR/MENU/COOK/REVIEW/PREP` 七大域。
- 依据：
  - `docs/superpowers/plans/2026-04-23-烟火小食单-研发拆分矩阵.md`
  - `docs/superpowers/plans/2026-04-23-烟火小食单-V1-研发执行批次.md`
  - `docs/db_init.sql`
- 约束（全局规范）：
  - 业务表保留 `remark VARCHAR(512) DEFAULT NULL`
  - 时间字段使用 `DATETIME(3)`（`created_at/updated_at`）

## 2. 建模原则

- 单一事实源：主数据尽量只在一张主表维护，关联信息放关系表。
- 扩展优先：新增字段优先 `NULL` + 默认值，减少对存量数据的破坏。
- 追踪可审计：所有核心业务动作至少具备可回溯的会话或关联 ID。
- 迁移可回放：DDL 按版本脚本执行，禁止只维护手工全量脚本。

## 3. Batch 1（基础底座）DDL

对应模块：`AUTH + DISH主数据 + INGR主数据`

### 3.1 AUTH 域

- `role`（已存在）
  - 保留：`id/name/remark/created_at/updated_at`
- `app_user`（已存在）
  - 建议新增（可选）：`phone VARCHAR(32)`（用于矩阵中的手机号校验）
- `user_role`（已存在）
  - 保留：用户-角色多对多唯一索引 `uk_user_role_user_role`

### 3.2 DISH 主数据域

- `dish`（已存在）
  - 保留：`name/cover_url/steps/notes/duration_min/difficulty/status`
  - 建议新增：`is_deleted TINYINT NOT NULL DEFAULT 0`（软删可选）
- `cuisine`（已存在）
- `tag`（已存在）
- `category`（已存在）
- 关系表（已存在）：
  - `dish_cuisine`
  - `dish_tag`
  - `dish_category`

### 3.3 INGR 主数据域

- `ingredient`（已存在）
  - 当前已有 `calories_kcal_per_100g`、`gi_value`
  - 若要严格对齐矩阵“蛋白质/脂肪等营养项”，建议新增：
    - `protein_g_per_100g DECIMAL(10,2) DEFAULT NULL`
    - `fat_g_per_100g DECIMAL(10,2) DEFAULT NULL`
    - `carb_g_per_100g DECIMAL(10,2) DEFAULT NULL`
- `dish_ingredient`（已存在）

## 4. Batch 2（主链路组装）DDL

对应模块：`DISH-INGR关联 + MENU + COOK`

### 4.1 MENU 域

- `menu_template`（已存在）
  - 保留：`template_type/scene/flavor/crowd/status/created_by`
  - 为支持“类型编码唯一”建议新增（可选二选一）：
    - 方案A：新增字典表 `menu_type_dict`
    - 方案B：`template_type` 固定枚举，不新增表
- `menu_template_dish`（已存在）

### 4.2 COOK 域

- `cooking_session`（已存在）
  - 保留：`user_id/template_id/status/started_at/ended_at`
  - 建议新增：`source_type TINYINT`（模板创建/自定义创建）
- `session_dish`（已存在）
  - 当前包含评分字段，适配基础点评能力

### 4.3 过程事件与复盘（矩阵要求，当前缺口）

矩阵中包含 `CookEvent`、`Retrospective`，但 `db_init.sql` 还未单独建表。建议新增：

- `cook_event`（建议新增）
  - 关键字段：`session_id/event_type/event_time/content/remark/created_at/updated_at`
  - 索引：`idx_ce_session_time(session_id, event_time)`
- `session_retrospective`（建议新增）
  - 关键字段：`session_id/summary/improvement/retry_advice/remark/created_at/updated_at`
  - 唯一约束：`uk_sr_session(session_id)`（每会话一条复盘，或改为多条历史版本）

## 5. Batch 3（业务闭环）DDL

对应模块：`PREP + REVIEW`

### 5.1 PREP 域

- `prep_item`（已存在）
  - 保留：`session_id/ingredient_id/plan_amount_g/actual_amount_g/status/note`
  - 建议新增：`is_shortage TINYINT NOT NULL DEFAULT 0`（缺货标记）

### 5.2 REVIEW 域（矩阵要求，当前缺口）

当前 `session_dish` 里已有部分评分字段，但矩阵定义为独立 review 能力（口味/难度/复做意愿/备注）。  
建议新增独立评价表，避免会话菜品表字段持续膨胀：

- `session_review`（建议新增）
  - 字段建议：
    - `id BIGINT PK`
    - `session_id BIGINT NOT NULL`
    - `dish_id BIGINT DEFAULT NULL`（按菜点评可填）
    - `taste_score TINYINT DEFAULT NULL`
    - `difficulty_score TINYINT DEFAULT NULL`
    - `retry_intent VARCHAR(16) DEFAULT NULL`
    - `review_note VARCHAR(500) DEFAULT NULL`
    - `remark VARCHAR(512) DEFAULT NULL`
    - `created_at/updated_at DATETIME(3)`
  - 约束：
    - 分值范围由业务与 CHECK（MySQL 8）共同保证
    - 索引：`idx_sr_session_id`、`idx_sr_dish_id`
