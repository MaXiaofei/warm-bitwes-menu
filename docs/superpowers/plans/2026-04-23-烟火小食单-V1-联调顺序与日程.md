# 烟火小食单 V1 联调顺序与日程（P0/P1/P2）

## 1. 目标

- 目标：按依赖顺序完成 V1 全链路联调，避免跨批次返工。
- 范围：对齐 `Batch 1/2/3`（对应 `P0/P1/P2`）。
- 依据：
  - `docs/superpowers/plans/2026-04-23-烟火小食单-V1-研发执行批次.md`
  - `docs/API规范执行清单.md`（第 8、11 章）

## 2. 联调总原则（门禁）

- **门禁 1（响应统一）**：所有联调接口必须返回 `ApiResponse<T>` 三段式。
- **门禁 2（错误码稳定）**：参数错误 `1001/1002`、权限 `2001/2002`、业务 `3001/3002`、系统 `5000`。
- **门禁 3（可回归）**：每个批次至少产出一组可复用的联调自测命令（curl/Postman）和验收记录。
- **门禁 4（不跨批次修补）**：上一批次未通过验收，禁止进入下一批次接口联调。

## 3. 环境与准备（一次性）

- **环境**：dev（独立数据库、独立配置）。
- **白名单可用**：`GET /menu/api/health`、`/swagger-ui/**`、`/v3/api-docs/**`。
- **接口前缀**：统一 `/menu/api`。
- **联调账号**：
  - `ADMIN`：后台能力
  - `USER`：小程序能力

## 4. 日程：Batch 1（P0，基础底座与主数据）

### 4.1 前置条件

- 全局异常与统一响应已贯通（参数校验/业务异常/系统异常）。
- `AUTH` 至少具备登录态（token）或临时放行联调用（两者择一，但必须有明确策略）。

### 4.2 联调步骤（建议 Day 1-2）

- **Step A：健康检查**
  - `GET /health`
  - 预期：`code=0`，`data="ok"` 或等价值

- **Step B：鉴权链路（最小可用）**
  - `POST /auth/login`
  - 预期：`data.accessToken/refreshToken/expiresIn` 存在
  - 失败预期：账号/密码错误返回 `3002`（或你定义的业务码，但必须稳定）

- **Step C：菜品主数据（DISH）**
  - `POST /dishes` -> `GET /dishes/{id}` -> `GET /dishes?pageNum=1&pageSize=10`
  - 覆盖：参数错误 `1001`、不存在 `3001`

- **Step D：食材主数据（INGR）**
  - `POST /ingredients` -> `GET /ingredients/{id}` -> `GET /ingredients?pageNum=1&pageSize=10`
  - 覆盖：名称唯一冲突 `3002`（或你定义的业务码）

- **Step E：字典类基础（菜系/分类/标签）**
  - `POST/PUT/GET /dish-cuisines`
  - `POST/PUT/GET /dish-categories`
  - `POST/PUT/GET /dish-tags`

### 4.3 验收口径（退出条件）

- 任一接口成功与失败均满足统一响应与错误码规则。
- 菜品与食材 CRUD + 分页联调通过；不存在资源返回 `3001`。
- 鉴权失败场景返回 `2001/2002`（若已接入权限控制）。

### 4.4 产出物

- 一份联调记录（包含：请求、响应、错误码覆盖点）。
- 一组可复用自测命令（建议保存到后续联调用例文档）。

## 5. 日程：Batch 2（P1，主链路组装）

### 5.1 前置条件

- Batch 1 验收通过并冻结（不再随意改返回结构/错误码）。
- 已具备 `dish`、`ingredient`、字典数据的最小测试数据。

### 5.2 联调步骤（建议 Day 3-5）

- **Step A：菜品-食材关联**
  - `PUT /dishes/{id}/ingredients`
  - `GET /dishes/{id}/ingredients`
  - 预期：重复绑定被拒绝（`3002`）

- **Step B：菜品图文（媒体/步骤）**
  - `PUT /dishes/{id}/steps`
  - `GET /dishes/{id}/media`

- **Step C：菜单模板（MENU）**
  - `POST /menu-templates` -> `GET /menu-templates/{id}` -> `GET /menu-templates?pageNum=1&pageSize=10`
  - `GET /menu-templates/{id}/ingredient-summary`
  - 预期：重复食材聚合正确；模板不存在 `3001`

- **Step D：做饭会话（COOK）**
  - `POST /cook-sessions`（模板创建或自定义创建）
  - `GET /cook-sessions/{id}`
  - `POST /cook-sessions/{id}/events` + `GET /cook-sessions/{id}/events`
  - `POST /cook-sessions/{id}/retrospectives` + `GET /cook-sessions/{id}/retrospectives`

### 5.3 验收口径（退出条件）

- “模板 -> 会话 -> 事件 -> 复盘”链路可完整跑通。
- 模板食材汇总与菜品食材关联一致。
- 会话状态流转与校验规则生效（非法状态操作返回 `3002`）。

### 5.4 产出物

- 主链路联调记录（建议包含 1 条完整演示脚本：从建菜品到会话复盘）。

## 6. 日程：Batch 3（P2，备菜与评价闭环）

### 6.1 前置条件

- Batch 2 主链路稳定且可重复跑通（同一套测试数据可复用）。

### 6.2 联调步骤（建议 Day 6-7）

- **Step A：备菜清单（PREP）**
  - `POST /cook-sessions/{id}/prep-list/generate`
  - `GET /cook-sessions/{id}/prep-list`
  - `GET /cook-sessions/{id}/prep-items`
  - `PUT /cook-sessions/{id}/prep-items/{itemId}/status`
  - `GET /cook-sessions/{id}/prep-progress`

- **Step B：缺货闭环**
  - `GET /cook-sessions/{id}/prep-shortages`
  - `POST /cook-sessions/{id}/prep-shortages/confirm`

- **Step C：点评（REVIEW）**
  - `POST /cook-sessions/{id}/reviews/taste`
  - `POST /cook-sessions/{id}/reviews/difficulty`
  - `POST /cook-sessions/{id}/reviews/retry-intent`
  - `POST /cook-sessions/{id}/reviews/note` + `PUT /cook-sessions/{id}/reviews/note`
  - `GET /cook-sessions/{id}/reviews`

### 6.3 验收口径（退出条件）

- 备菜生成的明细与模板食材汇总一致。
- 备菜状态只允许合法流转（非法流转返回 `3002`）。
- 评分范围校验生效（越界返回 `3002`），并可通过查询接口回看。

### 6.4 产出物

- 闭环联调演示脚本（一次会话从建模板到备菜到点评结束）。

## 7. 最终回归清单（全量）

- 白名单接口：`/health`、`/swagger-ui/**`、`/v3/api-docs/**`
- 鉴权错误：未带 token / token 过期 -> `2001`
- 权限错误：无权限访问 -> `2002`
- 参数错误：`1001/1002`
- 业务不存在：`3001`
- 状态非法/重复绑定/越界：`3002`
