# V1 Batch1 三端收口与分支合入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不动业务需求的前提下，把 `menu-admin`、`menu-mini` 上已存在于 `feat/batch1-*` 的工程与提交 **合入各仓库可协作的主线**（默认 `main`），并完成最小构建与测试验证；同时核对 `menu` 后端 Batch1 与 `docs/superpowers/specs/2026-05-09-三端开发进度与版本规划-design.md` 一致，为进入 Batch2 清障。

**Architecture:** 每个前端仓库在本地使用 **集成分支** `integrate/batch1-*` 承接 `origin/feat/batch1-*` 与 `origin/main` 的合并结果，验证通过后再在 **获得负责人明确同意** 的情况下合并到 `main`（避免在未授权时直接改主线，与 executing-plans 约束一致）。

**Tech Stack:** Git；`menu-admin`：Node 20、Vite 6、Vue 3、Vitest；`menu-mini`：Node 20、Vite 6、Vitest；`menu`：Java 17、Maven、JUnit 5。

**说明：** 下列步骤中的「提交」仅在你明确要求执行 `git commit` / `git push` 时执行；默认完成本地合并与验证即可。

### Task 1：`menu-admin` — 在集成分支上合并 Batch1 并跑通测试与构建

**Files:**

- 无必须改动的业务文件；若合并产生冲突，按冲突文件列表逐个解决（常见为 `package-lock.json`、`src/**`）。

- [ ] **Step 1：在 `feat/batch1-admin` 上做一次「干净构建」基线**

```bash
cd /Users/maxiaofei/mygithub/menu-admin
git fetch origin
git checkout feat/batch1-admin
git pull --ff-only origin feat/batch1-admin
npm ci
npm run test
npm run build
```

Run: 同上整段粘贴执行。

Expected: `npm run test` 与 `npm run build` 均 **退出码 0**。若失败，先在本分支修复后再进入 Step 2。

- [ ] **Step 2：从最新 `main` 创建集成分支并合并 `feat/batch1-admin`**

```bash
cd /Users/maxiaofei/mygithub/menu-admin
git checkout main
git pull --ff-only origin main
git checkout -b integrate/batch1-admin
git merge --no-ff origin/feat/batch1-admin -m "merge(integrate): feat/batch1-admin into integrate/batch1-admin"
```

Run: 同上。

Expected: 无冲突则直接进入 Step 3；若有冲突，`git status` 列出文件，人工解决后：

```bash
git add -A
git commit -m "merge(integrate): resolve conflicts with feat/batch1-admin"
```

- [ ] **Step 3：在集成分支上重复验证**

```bash

git checkout integrate/batch1-admin
npm ci
npm run test
npm run build
```

Expected: 全部 **退出码 0**。

- [ ] **Step 4（需负责人明确同意）：合并到 `main`**

仅在对方回复「同意合并 menu-admin 到 main」后执行：

