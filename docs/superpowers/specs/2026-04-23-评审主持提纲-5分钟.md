# 烟火小食单评审主持提纲（5分钟）

## 0. 会议目标（30秒）

- 目标：确认 `V1` 研发范围、分批顺序、验收口径。
- 展示材料：`烟火小食单.xmind` 中的 `研发版（评审精简视图）`。
- 评审规则：先看范围与顺序，细节争议会后分专题处理。

## 1. 结构说明（60秒）

- 当前使用统一结构：`模块 -> 能力 -> API -> 验收`。
- 覆盖 7 个核心域：`AUTH`、`DISH`、`INGR`、`MENU`、`COOK`、`REVIEW`、`PREP`。
- 每条能力均可回溯到产品节点 ID（`P-<DOMAIN>-NNN`），保证需求到研发一一映射。

## 2. V1范围冻结（90秒）

### 2.1 本次必做（V1）

- 权限与账号底座（`AUTH`）。
- 菜品/食材主数据与关联（`DISH` + `INGR`）。
- 菜单模板与场景匹配（`MENU`）。
- 烹饪会话与记录（`COOK`）。
- 备菜与点评复盘闭环（`PREP` + `REVIEW`）。

### 2.2 本次不做（延后到V2）

- 个性化推荐深度算法。
- 高级报表与复杂经营分析。
- 智能搭配与自动策略优化。

## 3. 分批实施（90秒）

### Batch 1（基础底座）

- 模块：`AUTH` + `DISH主数据` + `INGR主数据`
- 目标：打通权限和主数据 CRUD。
- 通过标准：越权访问拦截生效；主数据 CRUD + 分页可联调。

### Batch 2（主链路组装）

- 模块：`DISH-INGR关联` + `MENU` + `COOK`
- 目标：打通“模板 -> 会话 -> 记录”主流程。
- 通过标准：会话可创建、过程可记录、历史可查询。

### Batch 3（业务闭环）

- 模块：`PREP` + `REVIEW`
- 目标：完成“备菜 -> 烹饪 -> 点评复盘”闭环。
- 通过标准：清单可生成并跟踪；评分与复盘可提交回查。

## 4. 结论确认（60秒）

请评审人逐项给出明确结论（只答“通过/不通过”）：

- `V1` 范围是否冻结？
- 分批顺序是否认可？
- 每批验收口径是否可执行？

若任一项不通过：记录异议点与责任人，限时在会后 24 小时内给出修订版。

## 5. 会议结束动作（30秒）

- 会议结论同步到：
  - `docs/superpowers/plans/2026-04-23-烟火小食单-V1-研发执行批次.md`
  - `docs/superpowers/plans/2026-04-23-烟火小食单-研发拆分矩阵.md`
- 仅当三项结论全部通过时，进入研发排期和任务分配。
