> 本文对应实施计划 `docs/superpowers/plans/2026-05-09-V1-Batch2-三端实施计划.md` **Task 1**，并与产品批次 `docs/superpowers/plans/2026-04-23-烟火小食单-V1-研发执行批次.md` **Batch 2** 的三条验收检查点对齐。

## 2. 统一约定

- **响应体**：`code` / `message` / `data`（成功 `code=0`），与全局 API 规范一致。  
- **鉴权**：Batch2 新增或调整的受保护接口须定义权限点，并与 `menu-admin` 路由 `meta`、小程序请求头一致；具体码表见 `docs/superpowers/specs/2026-04-25-鉴权联调说明.md`（若与实现冲突以代码为准并回写本文）。  
- **时间字段**：请求/响应中涉及时间的，与库表一致使用毫秒精度语义（`LocalDateTime` 序列化格式在联调文档中固定一种，如 ISO-8601）。

## 3. 菜品、食材关联与模板食材汇总（B2-1）

### 3.1 菜品-食材全量替换

| 项目 | 说明 |
|------|------|
| 方法路径 | `PUT /api/dishes/{id}/ingredients` |
| 请求体 | `DishIngredientReplaceReq`：`items[]` 含 `ingredientId`、`amountG`、`sortOrder` |
| 成功 | `code=0`，`data` 可为 null |
| 失败 | 业务码由全局异常处理（如菜品不存在、食材不存在等） |

### 3.2 菜单模板与汇总

| 方法路径 | 说明 |
|----------|------|
| `POST /api/menu-templates` | 创建模板并绑定 `dishIds` |
| `GET /api/menu-templates` | 分页列表 `pageNum`、`pageSize` |
| `GET /api/menu-templates/{id}` | 详情（含 `dishIds`） |
| `GET /api/menu-templates/{id}/ingredient-summary` | **模板食材汇总**（B2-1 核心） |

**Batch2 待补（契约层）**

- 模板 **更新**（名称、类型、场景/人群、绑定菜品）是否需要 `PUT /api/menu-templates/{id}`：当前 Controller **未见**更新接口，若产品要求管理端可编辑，须在 Batch2 内新增并与本表同步。

### 3.3 菜品详情（含步骤/封面等，支撑 dish-media）

| 方法路径 | 说明 |
|----------|------|
| `GET /api/dishes/{id}` | 返回 `DishDetailVO`（含 `steps`、`coverUrl` 等，以实现为准） |
| `PUT /api/dishes/{id}` | 更新基础信息（含步骤/笔记等字段以 `DishUpdateReq` 为准） |

## 4. 会话创建（B2-2）

### 4.1 目标规则（契约）

- **`startedAt`**：**必填**。  
- **模板 vs 自选菜品（二选一）**  
  - **模式 A**：提供 `templateId`（非空），且 **不提供** `dishIds`，或 `dishIds` 为空。服务端写入 `cooking_session.template_id`，并可不写入 `session_dish`（或写入冗余快照，由实现选定，须在 Task 2 设计说明中写死一种）。  
  - **模式 B**：**不提供** `templateId` 或 `templateId=null`，且提供 **非空** `dishIds`。服务端 `cooking_session.template_id = NULL`，并在 `session_dish` 写入本次菜品及排序。  
- **禁止**：`templateId` 与 `dishIds` 同时有效、或两者皆空。

### 4.2 当前实现（基线）

| 项目 | 说明 |
|------|------|
| 方法路径 | `POST /api/cook-sessions` |
| 请求体 | `CookSessionCreateReq`：`templateId` `@NotNull`；`startedAt` `@NotNull` |
| 与目标差异 | 未支持模式 B；与 **§4.1** 不一致 → **Batch2 Task 2 必须改** |

### 4.3 建议请求体形态（实施后更新为「已上线」）

```json
{
  "templateId": null,
  "dishIds": [1, 2, 3],
  "startedAt": "2026-05-09T12:00:00"
}
```

或：

```json
{
  "templateId": 10,
  "dishIds": [],
  "startedAt": "2026-05-09T12:00:00"
}
```

（字段名以最终实现 DTO 为准，联调前在本文替换为正式表。）

## 5. 时间线、历史、复盘（B2-3）

### 5.1 数据表（`docs/db_init.sql` 摘要）

| 表 | 用途 |
|----|------|
| `cook_event` | 过程事件：`session_id`、`event_type`、`event_time`、`content` |
| `session_retrospective` | 复盘：每会话最多一行（`UNIQUE(session_id)`） |
| `cooking_session` | 会话主表：`status`、`started_at`、`ended_at` 等 |

### 5.2 目标 HTTP 契约（Batch2 内实现，当前多为**待实现**）

| 能力 | 建议路径（可微调，但须在合并前改本文） |
|------|----------------------------------------|
| 追加过程事件 | `POST /api/cook-sessions/{sessionId}/events` |
| 查询时间线 | `GET /api/cook-sessions/{sessionId}/events`（按 `event_time` 升序） |
| 写/更新复盘 | `PUT /api/cook-sessions/{sessionId}/retrospective`（UPSERT） |
| 读复盘 | `GET /api/cook-sessions/{sessionId}/retrospective` |
| 我的会话历史 | `GET /api/cook-sessions/mine?pageNum=&pageSize=`（仅当前用户） |

### 5.3 与现有接口的关系（避免 Batch3 混淆）

以下接口已在 `CookSessionController` 存在，**更贴近 Batch3**，Batch2 联调需约定是否对小程序开放或仅管理端/测试使用：

| 路径 | 说明 |
|------|------|
| `POST .../{sessionId}/prep-list/generate` | 备菜清单生成 |
| `POST .../{sessionId}/reviews/taste` | 口味评分 |
| `GET .../{sessionId}/reviews` | 点评列表 |

建议在 Batch2 **演示脚本**中二选一：要么纳入端到端演示，要么明确标注「Batch3 预置，Batch2 不验收」。
