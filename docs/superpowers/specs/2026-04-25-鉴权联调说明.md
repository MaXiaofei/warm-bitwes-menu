# 2026-04-25 鉴权联调说明

## 目标

统一说明 `menu` 后端当前鉴权规则，帮助 `menu-admin` 与 `menu-mini` 联调时快速判断：

- 什么 token 可以访问什么接口
- 不满足条件时返回什么业务码

## 登录与令牌

- 登录接口：`POST /api/auth/login`
- 入参：`username`、`password`、`clientType`
- 当前支持端类型：`admin`、`mini`
- 成功返回：`code=0`，`data.accessToken`、`data.refreshToken`、`data.expiresIn`
- 非法端类型：`code=10004`
- 账号或密码错误：`code=10001`

## 鉴权判定顺序

对于受保护接口（当前主要是 `/api/admin/**`），后端按以下顺序判定：

1. **是否带 Authorization**
   - 缺失或格式错误 -> `code=10002`
2. **token 是否可解析**
   - 无效 token -> `code=10002`
3. **端范围是否匹配**
   - 例如 `mini` token 访问 `/api/admin/**` -> `code=10003`
4. **权限点是否匹配**
   - 例如缺少 `auth-user:create` 调用新增用户接口 -> `code=10003`
5. 通过后执行业务逻辑
   - 成功 -> `code=0`

## 端与权限约定（当前实现）

- `admin` 登录：
  - 具备权限：`auth-user:list`、`auth-user:create`、`auth-role:grant`、`dish:view`、`ingredient:view`
  - 可访问管理端接口（还需满足具体接口权限点）
- `mini` 登录：
  - 具备权限：`dish:view`、`ingredient:view`
  - 不可访问 `/api/admin/**`

## 联调用例建议

### 1) admin 正向通过

- 使用 `clientType=admin` 登录拿 token
- 调用：`POST /api/admin/users`
- 期望：`code=0`

### 2) mini 越权拦截

- 使用 `clientType=mini` 登录拿 token
- 调用：`POST /api/admin/users`
- 期望：`code=10003`

### 3) admin 缺权限拦截

- 使用 admin token（但不含接口要求权限）调用受保护接口
- 期望：`code=10003`

### 4) 未登录拦截

- 不带 Authorization 头访问受保护接口
- 期望：`code=10002`

## 配套脚本

为方便联调，已提供两份脚本：

- 普通版（只打印响应）：`docs/superpowers/plans/2026-04-25-鉴权联调-curl.sh`
- 断言版（自动 PASS/FAIL）：`docs/superpowers/plans/2026-04-25-鉴权联调-curl-assert.sh`

推荐执行顺序：

1. 先跑普通版，确认服务连通与基础返回结构
2. 再跑断言版，快速得到回归结论

示例命令：

```bash
chmod +x "docs/superpowers/plans/2026-04-25-鉴权联调-curl.sh" \
  "docs/superpowers/plans/2026-04-25-鉴权联调-curl-assert.sh"

BASE_URL="http://localhost:8080" bash "docs/superpowers/plans/2026-04-25-鉴权联调-curl.sh"
BASE_URL="http://localhost:8080" bash "docs/superpowers/plans/2026-04-25-鉴权联调-curl-assert.sh"
```

断言版全绿时，输出末尾应类似：

```text
[PASS] admin login -> code=0
[PASS] admin login token extracted
[PASS] mini login -> code=0
[PASS] mini login token extracted
[PASS] admin token create user -> code=0
[PASS] mini token create user -> code=10003
[PASS] no token create user -> code=10002
[PASS] invalid token create user -> code=10002
ALL PASS: 鉴权联调用例全部通过。
```

## 响应格式约定

所有接口保持统一响应体：

- `code`: 业务码
- `message`: 描述信息
- `data`: 业务数据（失败时通常为 `null`）
